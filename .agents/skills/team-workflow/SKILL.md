# Team Workflow

Use this when the project needs shared context and coordinated execution.

## Workflow

1. Build shared context before execution: specs, ADRs, contracts, rules, and current plan.
2. Keep tasks at feature level; let agents split subtasks during execution.
3. Assign owners or agent roles for each workstream.
4. Use contracts to let domains work in parallel.
5. Review before merge or handoff.
6. Run a retrospective before the next sprint.

## Read As Needed

- Read `references/team-ai-workflow.md` for the workshop-derived workflow.
- Read `references/task-planning.md` when creating sprint tasks or backlog.
- Read `references/review-merge.md` when preparing review, merge, or handoff.

## Guardrails

- Do not turn a solo demo into a full team process.
- Do not split work without contracts or shared context.
- Do not let multiple agents edit the same files in parallel unless the boundaries are clear.
